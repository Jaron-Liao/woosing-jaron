# 微信内 H5 授权：需要准备什么 + 已完成的骨架

## 一、结论先说

| 问题 | 答案 |
|---|---|
| 微信内（内置浏览器）能不能直接授权登录？ | **能**，但只能走公众号 `snsapi_userinfo`，需要**已认证服务号** |
| 平台现有的 WorkBuddy OAuth 中继能不能做？ | **不能**。中继写死 `snsapi_login`（PC 扫码），微信内打开只会看到扫码页 |
| 拿到 openid 后能直接登录 CodeVerse 吗？ | **不能**。CloudBase 的 session 只能由 OAuth 回调或手机号 OTP 签发，没有「用 openid 换 session」的公开接口 |

所以完整链路是：**微信授权拿身份 → 绑定手机号 → 用 OTP 签发云端 session**。
微信那一步省掉的是「认人」，登录态那一步绕不开。

## 二、你需要准备的清单

| # | 项目 | 要求 | 成本 |
|---|---|---|---|
| 1 | 公众号类型 | **服务号**，且已完成微信认证（订阅号不支持网页授权） | 认证费 ¥300/年 |
| 2 | 网页授权域名 | 公众号后台「设置与开发 → 公众号设置 → 功能设置 → 网页授权域名」填写，需与后端 `BASE_URL` 完全一致 | 0 |
| 3 | 域名校验文件 | 把 `MP_verify_xxxx.txt` 放到域名根目录可访问（路径 `/MP_verify_xxxx.txt`） | 0 |
| 4 | AppID / AppSecret | 公众号后台「基本配置」里获取 | 0 |
| 5 | 服务器 IP 白名单 | 公众号后台「基本配置 → IP 白名单」加入服务出口 IP（不填则调接口报 40164） | 0 |
| 6 | 备案域名 | 中国大陆访问需要；未备案可用境外节点但慢 | 0（备案免费，耗时 7–20 工作日） |
| 7 | 后端服务 | 需要 Node 运行环境（用本次搭好的 `server/`） | 0 |
| 8 | 会话收口决策 | 见第四节，二选一 | — |

> 说明：**只有第 1 项要花钱**（认证费），其余都是配置。

## 三、已经搭好的东西（`server/`）

零依赖 Node 服务，同时托管 `dist/` 静态站和微信授权接口：

```
GET /health                     → { ok, wechatConfigured, missing }
GET /api/wechat/status          → { configured, scope }   前端据此决定是否显示「微信一键登录」
GET /api/wechat/authorize       → 302 到公众号授权页（state 用 HMAC 签名，10 分钟过期）
GET /api/wechat/callback        → code 换 openid（AppSecret 只在服务端），签发一次性 ticket，302 回前端
GET /api/wechat/profile?ticket= → 换昵称/头像（ticket 一次性、2 分钟过期）
```

已实现的安全与工程要点：
- 全部配置来自环境变量，启动时集中校验并告警缺失项；`AppSecret`、`TICKET_SECRET` 绝不进前端代码。
- `state` 用 HMAC-SHA256 签名 + 时间戳，`timingSafeEqual` 比对，防 CSRF 与重放。
- 票据存内存、一次性消费、2 分钟过期，openid 只回传脱敏形式（`wx_ab12***cd34`）。
- 结构化 JSON 日志 + 请求 ID；统一错误结构 `{ error, message }`，500 不外泄堆栈。
- `SIGTERM/SIGINT` 优雅停机。

### 本地跑起来

```bash
cd codeverse
cp server/.env.example server/.env      # 填入真实值（.env 已在 .gitignore）
set -a && source server/.env && set +a
PORT=4199 STATIC_DIR=dist node server/index.mjs
curl -s localhost:4199/health
```

### 已验证（假凭据下）

```
authorize            → 302 https://open.weixin.qq.com/connect/oauth2/authorize?appid=...&scope=snsapi_userinfo#wechat_redirect
callback 坏 state     → 400 {"error":"bad_state"}
callback 好 state+fake code → 502 {"error":"wechat_api_error","message":"微信接口返回 40013: invalid appid"}   ← 证明签名与调用链正确
profile 坏 ticket     → 400 {"error":"bad_ticket"}
```

## 四、还差一步：会话收口，二选一

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 微信身份 + 手机号绑定（推荐，最省事）** | 授权拿到 openid/昵称/头像 → 页面提示「最后一步：绑定手机号」→ 走现有 OTP 签发 session | 立刻可用，不依赖平台开放新能力 | 用户仍需收一次验证码 |
| **B. 自建账号体系** | 自己建 `cv_users` + `cv_wechat_binding` 表，用自建 JWT（httpOnly cookie）替代 CloudBase session | 微信内真正一键登录 | 要放弃 RLS 账号隔离、自己实现鉴权与数据权限，工作量最大 |

方案 A 我已经把前端也接好了：微信内且服务端已配置时，登录页会出现「微信一键登录」，授权回来自动显示头像昵称，再填手机号即可。**未配置时这个按钮不会出现**，静态部署不受任何影响。
